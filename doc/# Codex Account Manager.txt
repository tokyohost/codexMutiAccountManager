# Codex Account Manager

请帮我完整开发一个 Windows 桌面托盘应用：

**Codex Account Manager**

用于管理多个 ChatGPT Plus / Codex 登录账号，实现：

```text
Account A → CODEX_HOME=A
Account B → CODEX_HOME=B
Account C → CODEX_HOME=C
```

用户可以查看多个账号的 Codex 使用额度、刷新时间、当前账号，并可以一键切换账号。

项目需要直接做到可以运行、打包、通过 GitHub Actions 发布 Windows Installer。

不要只提供伪代码。

---

# 一、总体架构

采用：

```text
Python
    ↓
PySide6
    ↓
QSystemTrayIcon              Windows 系统托盘
QWebEngineView               内嵌 Vue3 页面
QWebChannel                  Vue3 ↔ Python IPC
    ↓
Vue3 + TypeScript + Vite
    ↓
现代化账号管理 UI
```

系统层全部由 Python 实现：

```text
Codex 进程管理
CODEX_HOME 管理
Windows 注册表环境变量
Codex App Server
文件复制
账号导入
额度读取
日志
```

UI 层全部使用 Vue3。

不要使用 PySide6 原生 QWidget 去绘制主要业务界面。

PySide6 原生界面只用于：

```text
系统托盘
主窗口容器
QWebEngineView
必要的原生确认框
```

主界面全部由 Vue3 实现。

# 五、异步任务设计

任何可能耗时的操作都绝对不能阻塞 Qt GUI 主线程。

例如：

```text
复制 CODEX_HOME
启动 codex app-server
读取额度
终止 Codex
刷新全部账号
```

都必须使用：

```text
QThreadPool
QRunnable
```

或者独立 QThread。

推荐：

```text
TaskManager
```

统一管理后台任务。

Python Bridge 发出事件：

```text
taskStarted
taskProgress
taskCompleted
taskFailed

accountChanged
accountUpdated
rateLimitsUpdated
```

Vue 根据这些事件更新 Pinia Store。

不要使用：

```python
while True
```

跑在 UI 主线程。

# 七、核心切换原则

这是整个软件最重要的原则。

禁止：

```text
Account A
  ↓
copy
  ↓
%USERPROFILE%\.codex

Account B
  ↓
copy overwrite
  ↓
%USERPROFILE%\.codex
```

不要每次切换账号时复制目录。

正确方式：

```text
Account A
 ↓
CODEX_HOME=C:\...\accounts\A\codex_home


Account B
 ↓
CODEX_HOME=C:\...\accounts\B\codex_home
```

也就是说：

**账号导入时复制一次。**

之后：

**永久直接使用该账号自己的 CODEX_HOME。**


只有验证通过：



# 十四、凭据存储模式

Codex 可能使用：

```text
file
keyring
auto
ephemeral
```

项目最适合：

```toml
cli_auth_credentials_store = "file"
```

此时认证保存在：

```text
CODEX_HOME\auth.json
```

如果导入后新 CODEX_HOME 无法读取账号，很可能当前账号使用了：

```text
Windows Credential Manager
```

这种情况下不要尝试读取 Windows Credential Manager 的 Token。

显示提示：

```text
当前 Codex 登录凭据没有随 CODEX_HOME 一起迁移。

建议将 Codex 设置为：

cli_auth_credentials_store = "file"

重新登录 Codex 后再次导入。
```

不要自动破解、导出或打印 Credential Manager 中的 Token。

# 十五、首次导入成功后的处理

假设用户原本使用：

```text
%USERPROFILE%\.codex
```

成功导入后：

```text
accounts\UUID-A\codex_home
```

应该询问用户：

```text
是否将当前 Codex 切换到由 Codex Account Manager 管理的账号目录？
```

默认推荐：

```text
是
```

之后：

```text
CODEX_HOME=<managed home>
```

这样以后 Token 自动刷新、session、history 全部直接写到 Managed Home。

原来的：

```text
%USERPROFILE%\.codex
```

不再作为活动账号使用。

# 四十八、PyInstaller

因为使用：

```text

```

**不要优先使用 PyInstaller `--onefile`。**

推荐：

```text

```

得到：

```text
dist\
└── CodexAccountManager\
    ├── CodexAccountManager.exe
    ├── Qt6...
    ├── resources...
    └── frontend...
```

然后由：

```text
Inno Setup
```

把整个目录封装成：

```text
CodexAccountManager-Setup-x64.exe
```

最终用户仍然只需要下载一个 Installer EXE。

这种方式比：

```text
PyInstaller --onefile + QtWebEngine
```

启动更快，也更稳定。
